# Общее описание
Игра в жанре 2d Adventure от третьего лица, стилизованная под квесты из 80х с командной строкой, такие как ранние игры от Sierra. Перемещения персонажа и осмотр предметов игрок выполняет с помощью Point-n-Click (для перемешения также можно использовать курсорные клавиши), всё остальное только с помощью команд. Таким образом, исключается прокликивание и бездумный перебор. Игрок должен придумать действие и написать его. Но если в классических квестах комстрока сковывала игрока и заставляла заниматься угадыванием глаголов, то у нас в качестве посредника между игроком и квестовым движком используется ИИ (языковая модель), который:
- читает ввод игрока, преобразовывает в действия квестового движка;
- придумывает тексты ответов, описания предметов/локаций и ведёт диалог c пользователем
- позволяет чатить с NPC напрямую, придумывая их реплики на лету.
Иными словами, ИИ играет роль посредника между движком игры и игроком, своеобразного гейм-мастера.

В прототипах в качестве ИИ может выступать "заглушка" из простого парсера или одна из больших языковых моделей через API. В конечном релизе планируется использовать локально работающую малую языковую модель, не требующую интернета.

# Основные элементы игры

## Спрайт
Это изображение (png с прозрачностью), которое может быть анимированным, то есть иметь несколько кадров, которые будут проигрываться по циклу.
Технически спрайт это JSON-объект, содержащий ссылку на графический файл, размер X/Y одного кадра, координаты его начала в png файле и количество кадров в анимации. Если спрайт не анимированный, то количество кадров в анимации равно 1. Кадры анимации в файле должны располагаться друг за другом по вертикали и иметь одинаковый размер.
Один и тот же png файл может быть использован для нескольких спрайтов, то есть служить атласом.

Каждый спрайт имеет уникальный id, который используется для ссылок на него.

## Сцена и объекты сцены
Сцена это отдельная локация, в которой находится персонаж игрока, и некоторые объекты. Может занимать один физический экран, либо быть больше его.  
Сцена может содержать _объекты_ следующих типов:
- *WalkBox*: замкнутый многоугольник, определяющий область, в которой можно перемещаться персонажем игрока (или NPC). Несколько WalkBox могут быть на одной сцене и взаимодействовать друг с другом, в зависимости от их типа: add, substract, invert;
- *TriggerBox*: замкнутый многоугольник, определяющий область, активирующую какие-то события и сюжетную логику, например коллайдер, попав в который персонаж игрока проваливается в люк, переносится в другую сцену, запускает диалог с NPC и т.п;
- *Static*: прямоугольник с координатами X/Y, размерами X/Y, цветом заполнения и опционально спрайтом/анимацией, отображающимся вместо прямоугольника. Спрайт можно переключать на лету. В основном Static это фоны, декоративные элементы и предметы, которые не перемещаются.
- *Actor*: объект, который помимо свойств Static имеет направление, в котором он повёрнут (вверх/вниз/влево/вправо) и, опционально, спрайты состояний (idle, walk, talk, etc), причём для каждого направления свой набор. Обычно Actor это NPC и анимированные объекты. Персонаж игрока также является разновидностью Actor. 

Объекты типа Static имеют уникальное свойство _Parallax_, управляющее их перемещением при движении камеры. При значении 1 они движутся так же, как другие объекты, при 0.5 движутся вдвое медленней, при 0 остаются вообще неподвижными, а при значениях >1, соответственно, движутся быстрее чем обычные объекты. Это позволяет делать параллаксные фоны с эффектом глубины. Например, спрайт с небом не движется при скроллинге сцены, спрайт с отдалёнными домами движется вдвое медленней, чем остальная сцена, а деревья на переднем плане -- чуть быстрее. 
Кроме того, Parallax влияет на порядок отрисовки: объекты с меньшим Parallax рисуются за объектами с большим Parallax.

Каждый объект имеет своё уникальное имя, которое используется для ссылок на него.

Сцена может поддерживать _Y-масштабирование_, имитирующее 3d перспективу, когда объекты, находящиеся "дальше от камеры" (то есть, выше по оси Y), становятся меньше. Настройки масштабирования для каждой сцены свои.
Кроме того, объекты типа Static и Actor имеют свойство, запрещающее их Y-масштабирование. Если Y-масштабирование объекта запрещено, то он не изменяет свой размер при изменении Y, даже если Y-масштабирование включено для сцены. Это полезно, например, для сцен, где персонаж лезет вертикально вверх по пожарной лестнице, и не должен уменьшаться по мере подъёма, поскольку не удаляется от камеры.

Сцена имеет свойство, определяющее _положение "камеры"_ (viewport), т.е. задаёт какая область сцены будет отображаться на экране и с каким зумом. Например, при приближении персонажа игрока к краю экрана сцена скроллится. По умолчанию камера позиционируется на персонаже игрока, но позиционированием можно управлять и динамически, например если игрок выходит из дома на улицу, то масштаб изображения может уменьшиться кастомной логикой (скриптом) этой сцены, отдалив камеру чтобы передать ощущение большого открытого пространства.
Чтобы облегчить манипуляции с камерой, сцена имеет два значения параметра zoom: дефолтный и текущий. Дефолтный zoom задаётся при создании сцены и применяется при её загрузке, а текущий -- изменяется динамически во время игры и при редактировании.

Каждая сцена имеет своё уникальное имя, которое используется для ссылок на неё.

# Игровая логика
Поскольку у нас игра в стиле Adventure, основанная на сюжетной логике, то нам нужно реагировать на:
- события, такие как стокновения Actor между собой, попадание их в TriggerBox,  
- условия, такие как наличие у игрока предмета в инветаре, текущей сцены, присутствия в ней NPC, состояния какой-то внутренней переменной
- команды игрока
- реплики игрока в диалоге NPC и ответы NPC на них

При этом в качестве реакции на это может потребоваться:
- изменение свойств сцены/объекта (например, скрыть/показать объект, приблизить или отдалить камеру)
- изменение состояния игры (например, изменить внутреннюю переменную timeOfDay на 'night')
- работа с инвентарём игрока (например, взять/забрать предмет)
- перенос игрока или NPC в другую сцену
- работа с анимациями объектов (например, персонаж садится на стул)
- и тд.

Комплексный пример: игрок подходит к стене, на которой есть кнопка. Если игрок находится рядом с кнопкой и отдаёт команду нажать на неё, сверху спускается лестница (не появляется, а именно плавно спускается), после чего становится доступна новая команда: "лезь по лестнице". Когда игрок переходит в режим лазания по лестнице, то обычный WalkBox отключается, а включается WalkBox для лазания по лестнице, который позволяет персонажу перемещаться лишь вверх и вниз. Кроме того, у персонажа игрока заменяются анимации walk для ходьбы вверх и вниз на анимации лазания вверх и вниз по лестнице, а ещё устанавливается запрет на Y-масштабирование, чтобы поднимаясь по лестнице персонаж не уменьшался в размере. Когда игрок долазит до TriggerBox вверху лестницы, он оказывается в другой сцене, при этом свойства его персонажа сбрасываются на дефолтные, то есть он вновь масштабируется и ходит, а не лазит. 
Очевидно, что такая кастомная логика требует какой-то системы, наподобие скриптов или наборов вложенных компонентов со свойствами и методами. 

[ ] Сейчас такой системы нет, но в будущем нам потребуется её разработать.

Важно отметить, что все свойства сцены и всех объектов должны быть доступны для изменения не только в редакторе, но и динамически прямо во время игры, со стороны игровой логики. Примерно как свойства в Unity или Unreal Engine.

# Редактор cцены 
Используется для создания/редактирования cцен и объектов. Включается по нажатию клавиши F1. 
Визуально отображается как набор UI элементов за пределами пользовательского игрового экрана:
- левая панель: список объектов сцены и настройки сцены
- правая панель: свойства выбранного объекта
- меню внизу экрана   

## Меню редактора сцены
Визуально это oldschool окошечки с F-клавишами в стиле Norton Commander:
F1 Game     F2 Save     F3 Load     F4 New     F5 Sprite   F9 Settings

При нажатии Shift: F2 Save As...

Пользователь может нажимать на них мышкой или использовать клавиатурные сочетания. 

- _Game_: Выключает редактор сцены и возвращает в режим игры
- _Save_: Сохраняет текущую сцену как JSON-файл
Если это новая сцена, или нажато Shift-F2, пользователю открывается системный диалог сохранения файла, в противном случае сцена просто сохраняется под текущим именем.  
- _Load_: Загружает сцену.
Пользователю открывается системный диалог выбора файла.
- _New_: Создаёт новую сцену из файла шаблона (default).
Если текущая сцена содержит несохранённые изменения, перед созданием или загрузкой новой сцены открывается системный поп-ап подтверждения.
- _Sprite_: Переход в редактор спрайтов.
- _Settings_: Открывает в правой панели глобальные настройки игры. Сейчас они ограничены только настройками шейдера CRT: 
    - _CRT MODE on/off_: включает/выключает все эффекты CRT (серый фон, искажения, scanlines, abberations)
    - _CRT geometry_: задаёт степень "выпуклости" экрана
    - _CRT scanlines_: размер scanlines
    - _CRT abberations_: степень искажения цветов (chromatic aberration)

## Список объектов сцены (левая панель)
Здесь отображается список всех объектов сцены в виде буква типа объекта : имя объекта.
Возможные типы:
- _S_: Static
- _A_: Actor
- _W_: WalkBox
- _T_: TriggerBox
Примеры: A:Player, S:Background01 
Длинный список может иметь ползунок прокрутки и может прокручиваться им, или колёсиком мыши при наведении на список. 
При нажатии мышкой на объект в списке он выделяется и открывается его настройки в правой панели.
Также можно выделить объект, просто кликнув на него на игровом экране.

Для создания нового объекта достаточно нажать на клавиатуре горячую клавишу - соответствующую букву (<S> для Static и тд.), при этом новый созданный объект сразу выделяется.
Для удаления надо выделить объект и нажать на клавиатуре <Del>.
В качестве альтернативы можно создавать объекты мышью через UI кнопку Add в верхней части панели, которое открывает выпадаюший список с типами объектов (и подсказку про их горячие клавиши), а удалять выделенный объект через UI кнопку Delete рядом с Add.

Выделенный объект можно сохранить в файл для последующего использования с помошью UI кнопки Save (или нажатия <Ctrl-S>), что откроет системный диалог сохранения файла.
Объект также можно загрузить в текущую сцену из файла с помощью UI кнопки Load (или нажатия <Ctrl-O>), что откроет системный диалог загрузки файла.

Объекты в списке можно перетаскивать мышью, чтобы изменить их порядок. Также можно использовать клавиатурные шорткаты <Ctrl-Up> и <Ctrl-Down>.

## Настройки сцены (Scene Properties)
Это отдельный пункт в левой панели над списком объектов. Его нельзя удалить, можно только выделить. При выделении в правой панели открываются свойства сцены:
- _Имя сцены_
- _Переключатель Y-масштабирования_ (on/off)
- _Настройки Y-масштабирования_ (мин и макс. умножители масштаба, уровень горизонта и уровень переднего плана)
- _Настройки камеры_: X/Y-координаты, умножитель масштаба камеры и переключатель автоматического центрирования камеры на игрока.
Настройки камеры могут меняться как через редактор, так и динамически, прямо в игре, через игровую логику. Например, в кат-сцене камера может сделать zoom-out, переместиться с игрока на другой объект, а затем вернуться обратно и восстановить zoom.
По умолчанию (если включено автоматическое центрирование) камера перемещается когда игрок подходим к краю экрана, что для пользователя выглядит как скроллинг.

## Отображение объектов на игровом экране в режиме редактирования сцены
Для удобства, все объекты типа WalkBox отображаются на главном игровом экране только тогда, когда выбран любой объект WalkBox в списке объектов, в противном случае они скрыты. То же самое с TriggerBox.

Пользователь может изменять текущий zoom сцены, нажимая на клавиши <+> и <->. Клавиша </> возвращает zoom к дефолтному значению.

Можно изменять координаты, на которые нацелена камера, заведя курсор мыши на игровой экран и двигая мышь с зажатой 3й кнопкой (<Middle>), что будет выглядеть как скроллинг сцены на экране. При кажатии клавиши <*> камера возвращается в дефолтное положение (центрируется на персонаже игрока, или на центр сцены).

Если пользователь сделал двойной клик на какой-то объект в списке на левой панели, то камера на игровом экране автоматически центрируется на этом объекте. 

Выбранный объект выделяется на игровом экране пунктирной рамкой, даже если он находится за другими объектами и скрыт ими, рамка рисуется поверх. Взявшись за объект или его рамку мышью, можно перетаскивать объект и изменять его координаты.

При создании нового многоугольного объекта WalkBox или TriggerBox пользователь должен последовательно задать мышью все его точки, и затем нажать клавишу <Enter> для завершения создания объекта и превращения его в замкнутую область.
Если пользователь выбрал другой объект не завершив создание многоугольника, при повторном выборе этого незавершённого объекта создание многоугольника будет начато заново.
Если при этом зажать <Shift>, то текущая задаваемая точка будет двигаться так, чтобы образовывать лишь углы кратные 18 градусам, для облегчения проведения строго вертикальных/горизонтальных линий, а также параллельных диагональных линий. 
Созданные многоугольные объекты WalkBox и TriggerBox можно редактировать, беря мышью за вершину многоугольника и двигая её. При этом также можно использовать <Shift> для ограничения движения вершины углами кратными 18 градусам.

## Настройки выбранного объекта (правая панель)
Здесь отображаются и доступны для редактирования все свойства выбранного объекта.

Для многоугольников тут также есть UI кнопка "Redraw", которая очищает многоугольник и запускает процесс его создания заново. 

Для Static есть UI кнопка "Sprite", открывающая системный файловый диалог для выбора спрайта (JSON-файла, создаваемого в редакторе спрайтов).

Для Actor можно создавать визуальные состояния (например, idle, walk, talk и т.д.), каждая из которых содержит имя состояния и 4 спрайта для всех 4 направлений (естественно любой спрайт в игре может быть анимированным). Состояния idle и walk обрабатываются автоматически, то есть если Actor движется, то он автоматически переходит в состояние walk если оно у него есть, а если стоит на месте, то в состояние idle если оно имеется.
Спрайты для состояний задаются через кнопки UI аналогично Static, с той разницей, что у Actor они динамически повяляются для каждого состояния.
Если спрайта для какого-то состояния или направления не задано, будет использоваться соответствующий из idle, а если и его нет, то Actor будет выглядеть как Static без спрайта, то есть как прямоугольник с заливкой цветом.

Для Actor и Static можно задать размер их прямоугольника (ширина и высота) а также масштаб их спрайта. Например, можно вдвое уменьшать масштаб предмета, чтобы использовать для него спрайты более высокого разрешения без увеличения размера на экране.

## Меню редактора спрайтов
F1 Scene Edit     F2 Save     F3 Load     F4 New     F5 Game

- _Scene Edit_: переход в редактор сцены;
- _Save_: сохраняет текущий спрайт как JSON-файл;
- _Load_: загружает спрайт из файла;
- _New_: создаёт новый спрайт;
- _Game_: переход в игру (закрывает редактор спрайтов);
