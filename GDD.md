# Общее описание

Игра в жанре 2d Adventure от третьего лица, стилизованная под квесты из 80х с командной строкой, такие как ранние игры от Sierra, и LucasArts. Используется гибридное управление: перемещения персонажа, осмотр предметов и рутинное взаимодействие с окружением (открой/закрой) игрок выполняет с помощью Point-n-Click (для перемешения также можно использовать курсорные клавиши), всё остальное только с помощью текстовых команд (при желании командами также можно делать всё, что можно делать через Point-n-Click). Таким образом, исключается прокликивание и бездумный перебор. Игрок должен придумать действие и написать его. Но если в классических квестах комстрока сковывала игрока и заставляла заниматься угадыванием глаголов, то у нас в качестве посредника между игроком и квестовым движком используется ИИ (языковая модель), который:

- читает ввод игрока, преобразовывает в действия квестового движка;
- придумывает тексты ответов, описания предметов/локаций и ведёт диалог c пользователем
- позволяет чатить с NPC напрямую, придумывая их реплики на лету.

# Текстовый интерфейс

Наша игра продолжает традиции классических Adventure, которые когда-то были полностью текстовыми. Кроме того, нарратив связан с темой компьютеров. Поэтому у нас есть классическая "консоль терминала" со строкой ввода команд и областью вывода сообщений над ней (буфер консоли). В этот буфер выводятся все введенные пользователем команды и все игровые сообщения (за исключением неигровых, служебных уведомлений движка и редактора сцены, которые выводятся через toast notifications).
Есть два основных формата пользовательского ввода:

- **Команда**: указание что нужно сделать, напр. "открой дверь ключом";
- **Реплика**: прямой текст, который произносит герой и который "слышат" все NPC находяшиеся в сцене. Начинается с символа "-".
  > Режим команд является основным, и пользователь может давать команду парсеру сегенерировать реплику за него, напр. "Расскажи Линде про то, что видел по дороге".

## Виртуальная консоль

Консоль имеет _три_ состояния:

- **закрытое**;
- **закрытое модальное**;
- **открытое**.
  В _закрытом_ состоянии пользователь видит только последние две строки буфера консоли в нижней части экрана, и под ними строку ввода команды.
  При нажатии на специальную клавишу на клавиатуре (тильда ~) консоль _открывается_ поверх картинки, почти на весь игровой экран, накладываясь на него с небольшой полупрозрачностью. При этом, в закрытом виде консоль и строка ввода интегрированы в игровую картинку, то есть рисуются на low-res 2d канвасе и поверх накладывается CRT фильтр. В открытом же виде консоль рисуется поверх игровой картинки, в том же слое, что UI редактора, в высоком разрешении, без CRT фильтра,чтобы пользователям было комфортно читать текст. Строка ввода работает и в открытом состоянии, так что пользователи могут вводить команды в консоль не закрывая её.
  Для показа важных сообщений, которые не влазят в 2 строки закрытой консоли, она может переходить в _модальный_ режим, когда командная строка убирается, а если текст сообщения не помещается и в три строки, то высота области буфера увеличивается на нужное число строк, чтобы текст сообщения выводился поверх картинки. В модальном режиме после текста сообщения всегда идёт надпись "[Continue]" и ожидается нажатие любой клавиши или клик мыши, после чего происходит переход в обычный режим.
  Открытая консоль не переходит в модальный режим.
  Текст открытой консоли можно прокручивать колесом мыши или клавишами Page Up/Down чтобы увидеть более ранние сообщения. Буфер должен быть достаточно большим, порядка 150 Kb. При сохранении игры в файл буфер сохраняется вместе с игрой.

## Строка ввода команды

Когда пользователь вводит команду и нажимает Enter, эта команда выводится в буфер консоли (цветом, отличным от цвета вывода сообщений), и затем отправляется в парсер для обработки.
Доступна история команд (хранится порядка 50 последних команд), переключаться между которыми можно курсорными стрелками вверх/вниз с зажатой клавишей <Ctrl>. История команд сохранятеся вместе с игрой.
Также можно быстро очистить строку ввода, нажав <Ctrl>+<Backspace>.

## Парсер - посредник

Парсер играет роль **посредника** между движком игры и игроком, своеобразного гейм-мастера. Он принимает пользовательский ввод, наряду с контекстом (информацией о сцене, находящихся в ней предметах и NPC, доступны действиях и состояниях). Затем парсер обрабатывает это и даёт команды игровому движку через API, опционально получает возвращаемые API значения и составляет сообщения для пользователя.

<Context> ---json--> | | | |
| | ---text--> | <Parser> | ---json--> | <API> |
| <User> | <--text--- | | <--------- | |
| |

Parser обрабатывает пользовательский ввод каскадно, если каскад не смог обработать команду, она передаётся следующему:

1. Простой разбор через regexps, распознающий самые элементарные команды типа look [at], take [up], drop, use <> with <>, i (inventory), а также служебные команды save, load, run, etc. (мгновенно);
2. Малая локальная нейросеть, например nlp.js (быстро, порядка 50 ms);
3. Средняя (или малая) языковая модель, работающая локально или через API. (очень медленно и "дорого")

Первые два каскада парсят почти весь нормальный пользовательский ввод, а LLM/SLM подключается только если ввод не распознан ни одним из них, либо надо сгенерировать текст, в том числе при прямых диалогах с NPC.
В любом случае, на выходе парсера получается json с набором вызовов API. Затем парсер анализирует их результат (то, что возвращают методы API) и осуществляет какое-то действие: либо отправляет новый json c вызовами API и уходит на новую итерацию, либо отправляет пользователю итоговое сообщение в консоль и заканчивает обработку команды.

> В данный момент Parser находится в зачаточном состоянии, реализован только первый каскад, и мы отлаживаем на нём взаимодействие с API. Впоследствии остальные каскады будут использовать ту же систему.

# Основные элементы игры

## Спрайт

Это изображение, которое может быть анимированным, то есть иметь несколько кадров, которые будут проигрываться по циклу.
Технически спрайт это JSON-объект, содержащий ссылку на графический файл (png с прозрачностью), размер X/Y одного кадра, координаты его начала в png файле и количество кадров в анимации. Если спрайт не анимированный, то количество кадров в анимации равно 1. Кадры анимации в файле должны располагаться друг за другом по вертикали и иметь одинаковый размер.
Один и тот же png файл может быть использован для нескольких спрайтов, то есть служить атласом.

Каждый спрайт имеет уникальный id, который используется для ссылок на него.

## Сцена и объекты сцены

Сцена это отдельная локация, в которой находится персонаж игрока, и другие объекты. Может занимать один физический экран, либо быть больше его.  
Сцена может содержать _объекты_ следующих типов:

- _WalkBox_: замкнутый многоугольник, определяющий область, в которой можно перемещаться персонажем игрока (или NPC). Несколько WalkBox могут быть на одной сцене и взаимодействовать друг с другом, в зависимости от их типа: add, substract, invert;
- _TriggerBox_: замкнутый многоугольник, определяющий область, активирующую какие-то события и сюжетную логику, например коллайдер, попав в который персонаж игрока проваливается в люк, переносится в другую сцену, запускает диалог с NPC и т.п;
- _Static_: прямоугольник с координатами X/Y, размерами X/Y, цветом заполнения и опционально спрайтом/анимацией, отображающимся вместо прямоугольника. Спрайт можно переключать на лету. В основном Static это фоны, декоративные элементы и предметы, которые не перемещаются.
- _Actor_: объект, который помимо свойств Static имеет направление, в котором он повёрнут и, опционально, спрайты/анимации состояний (idle, walk, talk, etc), причём для каждого направления свой набор. Обычно Actor это NPC и анимированные объекты. Персонаж игрока также является разновидностью Actor.

Каждая сцена и каждый объект имеют свой уникальный _ID_, который используется для ссылок на них. При этом:

1. id (содержимое поля id/file) для сцен, спрайтов, и также префабов (т.е. сохранённых объектов) может включать один или несколько обратных слешей "\". При сохранении такого объекта слеши работают как маркеры подпапок (относительно дефолтной папки для данного типа объектов), например "home\room1" сохранится как файл room.json в папке home.
2. При загрузке такого объекта его id не читается из файла, а формируется с учётом пути относительно дефолтной папки и имени файла, таким образом этот объект загрузится c id "home\room1" а не "room1". Соответственно, если пользователь нажмёт "Save", объект сохранится не в дефолтной папке а в подпапке home как room1.
3. При завершении загрузки объекта сформированный id дополнительно проверяется на предмет совпадения с уже имеющимися в сцене. Если это не уникальный id, то он дополняется до уникального.
4. API при создании объекта или загрузки сцены получает id, трактует его как имя файла с возможным учётом подпапок и загружает его оттуда.

Сцена может поддерживать _Depth-scaling_ -- масштабирование объектов, имитирующее 3d перспективу, когда объекты, находящиеся "дальше от камеры" (то есть, выше по оси Y), становятся меньше. Настройки масштабирования для каждой сцены свои.
Кроме того, объекты типа Static и Actor имеют свойство, запрещающее их Depth-scaling. Если Depth-scaling объекта запрещен, то он не изменяет свой размер при изменении Y, даже если Depth-scaling включен для сцены. Это полезно, например, для сцен, где персонаж лезет вертикально вверх по пожарной лестнице, и не должен уменьшаться по мере подъёма, поскольку не удаляется от камеры.

Сцена имеет свойство, определяющее _положение "камеры"_ (viewport), т.е. задаёт какая область сцены будет отображаться на экране и с каким зумом. Например, при приближении персонажа игрока к краю экрана сцена скроллится. По умолчанию камера позиционируется на персонаже игрока, но позиционированием можно управлять и динамически, например если игрок выходит из дома на улицу, то масштаб изображения может уменьшиться кастомной логикой (скриптом) этой сцены, отдалив камеру чтобы передать ощущение большого открытого пространства.
Чтобы облегчить манипуляции с камерой, сцена имеет два значения параметра zoom: дефолтный и текущий. Дефолтный zoom задаётся при создании сцены и применяется при её загрузке, а текущий -- изменяется динамически во время игры и при редактировании.

Важно отметить, что все свойства сцены и всех объектов должны быть доступны для изменения не только в редакторе, но и динамически прямо во время игры, со стороны игровой логики (скриптов). Примерно как свойства в Unity или Unreal Engine.

## Структура классов

С точки зрения кода класс _SceneObject_ является прародительским для всех объектов сцены в игре, включая Static, Actor, а также полигональные объекты TriggerBox и WalkBox.

SceneObject
├── PolygonObject
│ ├── Walkbox
│ └── Triggerbox
├── QuadObject
└── Entity (≈ Static)
└── Actor

## Свойства объектов SceneObject

Эти свойства наследуются всеми объектами в игре:

_ID_ : (string)
Уникальный идентификатор объекта, который используется для его идентификации в сцене и для загрузки префаба объекта из файла (см. выше).

_GroupID_ : (string or nil)
Уникальный идентификатор (тэг) группы объектов, который используется для операций над всей группой (например, включить/выключить или передвинуть). Группа является чисто виртуальным множеством, она не сохраняется как префаб.
ID группы всегда начинается с символа `#` (например, `#myGroup`).
Один объект может принадлежать нескольким группам (например, `#lights, #furniture`).

_Disabled_ : (boolean)
Любой объект сцены может быть выключен (Disabled), то есть не отображаться и не реагировать на события.

_Locked_ : (boolean)
Объект может быть заблокирован (Locked) для редактирования в редакторе сцены. Заблокированные объекты нельзя выбрать или переместить кликом мыши на экране (они становятся "прозрачными" для кликов), но их всё ещё можно выбрать в списке объектов. В режиме игры это свойство игнорируется.

## Коллайдеры (Collision Box)

Объекты типа Static и Actor имеют свойства `Collider Width` и `Collider Height`, задающие размер прямоугольной области столкновения, которая по X центрирована по объекту, а по Y нижняя граница прямоугольника коллайдера приходится на нижнюю границу спрайта/прямоугольника объекта. То есть, при увеличении высоты коллайдера он растёт вверх, а при увеличении ширины он растёт в обе стороны от центра объекта.

- Если размеры коллайдера больше 0, этот объект является препятствием для других объектов (Actor), имеющих коллайдер.
- Коллайдер взаимодействует с WalkBox:
  - В режиме _Subtract_: WalkBox вырезает "дыру". Если коллайдер объекта пересекается с ней, движение блокируется;
  - В режиме _Invert_: коллайдер объекта должен полностью находиться внутри разрешенной зоны.
- Если размеры коллайдера равны 0, объект считается проходимым, не сталкивается с другими и игнорирует WalkBox.

## Свойства Static

_Parallax_
Управляет их перемещением при движении камеры. При значении 1 они движутся так же, как другие объекты, при 0.5 движутся вдвое медленней, при 0 остаются вообще неподвижными, а при значениях >1, соответственно, движутся быстрее чем обычные объекты. Это позволяет делать параллаксные фоны с эффектом глубины. Например, спрайт с небом не движется при скроллинге сцены, спрайт с отдалёнными домами движется вдвое медленней, чем остальная сцена, а деревья на переднем плане -- чуть быстрее.
Кроме того, Parallax влияет на порядок отрисовки: объекты с меньшим Parallax рисуются за объектами с большим Parallax.

_Layer_
Управляет порядком отрисовки объектов без параллакса. Объекты с меньшим Layer рисуются за объектами с большим Layer.

_Visual Effects_

- **Opacity**: Прозрачность объекта (0.0 - 1.0).
- **Blend Mode**: Режим наложения цвета (Normal, Multiply, Screen, Overlay, etc).
- **Blur**: Эффект размытия (в пикселях).

## Свойства Actor

Actor это расширение Static. Помимо текущего спрайта, как у Static, имеет направление и (опционально) визуальное состояние.

_Direction_ : string (4 возможных значения: up, down, left, right).

_Visual State_ : string or nil
У Actor может иметься текущее визуальное состояние (idle, walk, talk, etc.) с которым связан набор спрайтов (группа анимаций), содержащий спрайты для каждого направления. При изменении визуального состояния или направления Actor автоматически копирует спрайты из соответствующейгруппы в текущий спрайт (если спрайты заданы).
Actor может иметь сколько угодно групп анимаций при условии, что их id будут уникальными.
При отображении стояния на месте и ходьбы Actor (например игрока) игра должна использовать группы с предопределёнными id 'idle' и 'walk', если они есть у Actor.

Для скриптов есть возможность через API переключать состояние. Например, если переключить на группу "talk", то персонаж будет воспроизводить анимации разговора в зависимости от того, куда он повёрнут. Он будет сохранять эту анимацию до тех пор, пока ему не придёт команда перемещаться, тогда он переключится на walk а после остановки автоматически на idle.

## Свойства Quad

_Quad_ это примитив, определяемый четырьмя вершинами. В отличие от Static, это не прямоугольник, а произвольный четырёхугольник. Основное назначение -- создание поверхностей и стен с учётом 2.5D перспективы, а также эффектов тени и освещения.

_Vertices_
Quad имеет 4 вершины. У каждой вершины свои координаты X, Y и свой коэффициент Parallax (P). Это позволяет создавать объекты, которые корректно деформируются при движении камеры, имитируя 3D перспективу. Например, "пол" будет иметь вершины с разным параллаксом: ближние к камере P > 1, дальние P < 1.

_Retro Grid Mode_
Quad может отображаться как "сетка" (Retro-Grid), что соответствует стилистике ретро-футуризма 80х. Настраивается цвет линий, толщина и количество ячеек сетки. Этот режим не отменяет заливку цветом и может использоваться одновременно с ней.

_Sort Mode_ (v0, v1, v2, v3, ignore)
Определяет точку сортировки (Z-Sort) для объекта. Поскольку Quad может быть сильно вытянут в глубину (наподобие пола), его центр может быть некорректной точкой для сортировки относительно других объектов (например, персонажа стоящего на этом полу). Режим сортировки позволяет привязать Z-индекс к конкретной вершине (например, самой дальней).

## Компонентная система

Кроме простых свойств, которые есть всегда, объекты сцены могут содержать компоненты (структуры данных), которые могут быть добавлены и удалены в редакторе. Каждый объект может иметь один или несколько компонентов разных типов. Но не любой объект может содержать любой компонент.
Каждый компонент имеет уникальный id компонента.

#### Компоненты групп анимаций

Есть только у Actor.

Каждый компонент имеет id группы анимаций и 4 спрайта для каждого направления.

> Если левый спрайт не задан, для него будет использован отзеркаленный правый спрайт.

##### Поле targed ID

Компонент может иметь поле `targetID`, определяющее целевой список объектов, к которым он относится.
Поле может содержать ID группы (напр. `#table_items`), ID конкретного объекта (напр. `apple`) или список целей через запятую (напр. `#desk, lamp`).

#### Компоненты теней (Shadow)

Есть только у Actor.

- _Shadow_ (shadowQuadId, offsetX, offsetY, triggerId) : Управляет отображением тени.
  - _shadowQuadId_: ID существующего объекта Quad (не группы!), который будет использоваться как тень.
  - _offset X/Y_: Смещение первой (нулевой) вершины Quad относительно координат Actor. Остальные вершины перемещаются синхронно, сохраняя форму Quad.
  - _trigger ID_: Unified Target Reference (ID объекта или группы `#group`), определяющий зоны, где тень должна быть видна.
    Тень отображается (объект shadowQuadId включается), когда центр Actor находится внутри одного из объектов, заданных в trigger ID. Используется Pixel-perfect проверка попадания.
    Вне этих зон тень автоматически выключается (Disabled).

#### Компоненты триггеров

Есть только у TriggerBox.

Триггеры предназначены для обработки событий в игре, таких как переходы между сценами, открытие/закрытие дверей и контейнеров, взаимодействие с предметами и т.д.

- _Exit_ (id сцены, id TriggerBox) : попадание в такой триггер вызывает перенос персонажа игрока в сцену с указанным id и в TriggerBox с id, указанном в компоненте. id сцены может указывать и на текущею сцену, тогда персонаж игрока будет телепортирован в TriggerBox текущей сцены.

- _Entry_ (направление): Ответный триггер по отношению к Exit, он обозначает ту точку в сцене, куда перемещается Actor при переходе, а также направление, в котором он будет находиться при появлении.

- _Subscene_ (targetID, [Name]) : Триггер, который при клике мышью или по команде "осмотреть Name" открывает крупный план чего-то поверх затемнённой/заблюренной текущей сцены. Например, игрок кликает по столу и ему открывается крупный план стола как "картинка в картинке".
  Технически это просто включение (Enable) указанных целей. Для выхода обратно в главную сцену игрок должен кликнуть за пределами объектов этой группы.
  Пока открыта Subscene передвижения персонажа игрока заблокированы.

> Если триггер Subscene относится к переключаемой им группе объектов (имеет такой Group ID как Group_id_1 или Group_id_2), то он не дизейблит самого себя, чтобы не сломать логику переключения. Но другие объекты, которые находятся в этой группе, включая триггеры, будут дизейблиться.

- _Switch_ (Target_ID_1, Target_ID_2, state (1 or 2), [Name], [id_key], [sound_1], [sound_2]) : Триггер, который при клике мышью или по команде "открыть Name" подменяет одни объекты другими, а при повторном клике или команде "закрыть Name" подменяет обратно. Например, игрок кликает по двери и она открывается, а при повторном клике закрывается. Технически "открытие/закрытие" это включение одной и выключение другой группы объектов сцены (или subscene).

Если указан id_key, то объект открывается только если в инвентаре есть предмет с таким id.
Опционально можно задать имена звуковых файлов для сопровождения открытия и закрытия.

> **Автосброс в Subscene**: Если Switch находится внутри Subscene, то при выходе из этой Subscene он автоматически сбрасывается в состояние 1 (Закрыто), со звуковым сопровождением (sound_1), чтобы избежать рассинхронизации с основной сценой и ситуаций когда там объект закрыт а в сабсцене открыт.

- _Subtrigger_ (id) : дополнительная область, отлавливающая клики по ней, и триггерящая другой TriggerBox с заданным id, как будто кликнули по нему.
  Полезно для случаев, наподобие выдвигаемого по Switch ящика стола, который в выдвинутом виде находится за пределами своего Switch и нуждается в доп. области для его активации.

#### Компоненты объектов

Есть у Static, Actor и Quad.

- _Item_ () : Объект, который можно взять и хранить в инвентаре, т.е. поднимаемый предмет. Свойства:
  - Ignore distance (boolean): если true, то расстояние от персонажа игрока до объекта игнорируется и он может быть всегда взят;

> компонент Item может быть только один у объекта.

- _State_ () : Состояние объекта, например открыт/закрыт, включено/выключено, etc.
  Состояния это по сути переменные или свойства объекта, которые могут быть изменены скриптом. Они имеют поля:
  - тип: string, number, boolean;
  - начальное значение;

Скриптовое API позволяет получать и устанавливать любые State любого объекта, но не позволяет создавать новые. Пользователь должен явно создать их в реакторе.

Visual_State (который есть у Actor, см. выше), это специальный предопределённый State, который влияет на визуальное отображение объекта, просто для удобства оформлен не как компонент, а как отдельное поле. Пользователь не может создать State с именем Visul_State, посколько оно зарезервировано компонентом у всех Actor. Но с точки зрения скриптового API состояние Visual_State может быть установлено и прочитано как любой другой State.

#### Компоненты Quad

- _Backface_ (targetID, cullingType) : Компонент для скрытия/показа любых объектов (Static, Actor, Quad) в зависимости от того, находится ли объект-владелец "лицом" или "спиной" к камере (определяется сравнением визуальных координат вершин владельца).
  - targetID: ID целей, которыми управляет данный компонент (скрывает/показывает).
    **Unified Target:** Поддерживает смешанные списки групп `#group` и объектов `id`. По умолчанию (если пусто) управляет самим владельцем.
  - cullingType: Режим работы.
    - 'render' (default): полностью отключает рендеринг целевых объектов (visible = false).
    - 'layer': перемещает целевые объекты на слой ниже (-1) и обратно, позволяя сортировать их позади других объектов.

#### Скриптовые события

Static и Actor могут содержать скриптовые события (interactions).
Каждое событие имеет ассоциированный с ним ID скрипта, который будет выполнен при наступлении события.

Типы событий, обрабатываемых парсером:

- _LOOK_ / _EXAMINE_ : Вызывается при осмотре объекта (команда `look <obj>`).
- _PICKUP_ / _TAKE_ : Вызывается при попытке взять объект (команда `take <obj>`). Если скрипт не задан, срабатывает стандартная логика (проверка компонента Item).
- _USE_ : Вызывается при использовании объекта (команда `use <obj>`).
- _USE <ITEM_ID>_ : Вызывается при использовании конкретного предмета из инвентаря на данном объекте (команда `use <item> on <obj>`). В этом случае ключом события является ID (или имя) применяемого предмета в верхнем регистре (например, `KEY_CARD`).

> Примечание: События _Always_ и _OnCollide_ зарезервированы в дизайне, но на текущий момент технически не реализованы в движке.

# Игровая логика (API & scripting system)

Поскольку у нас игра, основанная на сюжетной логике, то нам нужно реагировать на события, такие как:

- столкновения Actor между собой, попадание их в TriggerBox,
- условия, такие как наличие у игрока предмета в инветаре, текущей сцены, присутствия в ней NPC, состояния какой-то внутренней переменной
- команды игрока
- реплики игрока в диалоге NPC и ответы NPC на них

При этом в качестве реакции на это может потребоваться:

- изменение свойств сцены/объекта (например, скрыть/показать объект, приблизить или отдалить камеру)
- изменение состояния игры (например, изменить внутреннюю переменную timeOfDay на 'night')
- работа с инвентарём игрока (например, взять/забрать предмет)
- перенос игрока или NPC в другую сцену
- работа с анимациями объектов (например, персонаж садится на стул)
- и тд.

Комплексный пример: игрок подходит к стене, на которой есть кнопка. Если игрок находится рядом с кнопкой и отдаёт команду нажать на неё, сверху спускается лестница, после чего становится доступна новая команда: "лезь по лестнице". Когда игрок переходит в режим лазания по лестнице, то обычный WalkBox отключается, а включается WalkBox для лестницы, который позволяет персонажу перемещаться лишь вверх и вниз. Кроме того, у персонажа игрока заменяются анимации walk для ходьбы вверх и вниз на анимации лазания вверх и вниз по лестнице, а ещё устанавливается запрет на Depth-scaling, чтобы поднимаясь по лестнице персонаж не уменьшался в размере. Когда игрок долазит до TriggerBox вверху лестницы, он оказывается в другой сцене, при этом свойства его персонажа сбрасываются на дефолтные, то есть он вновь масштабируется и ходит, а не лазит.

Очевидно, что это требует какой-то системы скриптов. Для этого мы используем тот же язык, на котором написан движок, то есть Typescript с паттерном Script Registry и API для взаимодействия с игрой.

> Парсер и UI используют этот же API. Например, если пользователь ввёл команду Look <объект> или кликнул наэтот объект, вызовется game.look(object_id)

## API

Все скрипты регистрируются в `ScriptRegistry` и получают объект контекста `ScriptContext` со следующими аргументами:

- `game`: Ссылка на основной экземпляр игры (`Game.instance`).
- `entity`: Ссылка на объект, на котором сработал скрипт (Entity/Actor/Triggerbox).
- `args`: Опциональные дополнительные аргументы.

### Основные методы

#### Game

- `game.showMessage(text: string)`: Выводит сообщение в игровую консоль/UI.
- `game.playSound(filename: string)`: Проигрывает звуковой файл из папки `public/sounds`.
- `game.sceneManager.switchTo(sceneId: string)`: Загружает и переключает на указанную сцену.

- 'game.look()'

#### Entity / Actor

- `entity.setSprite(filename: string)`: Меняет спрайт объекта.
- `entity.description = "..."`: Меняет описание объекта (для команды look).
- `actor.setDirection(dir: 'up'|'down'|'left'|'right')`: Поворачивает персонажа.
- `actor.playAnimSet(id: string)`: Переключает набор анимаций (например, на 'talk').
- `actor.resetAnimSet()`: Возвращает набор анимаций к дефолтному ('idle'/'walk').
- `actor.walkTo(x, y)`: Заставляет персонажа идти в указанную точку (с учетом Walkbox).
- `actor.stop()`: Останавливает движение.

### Пример скрипта

```typescript
ScriptRegistry.register('interaction.pillar.key', ({ game, entity }) => {
  game.showMessage('You insert the key into a hidden slot in the pillar.');
  game.playSound('secret_reveal.wav');

  // Change pillar appearance
  entity.setSprite('pillar_open');
  entity.description = 'The pillar is open.';
});
```

### Регистрация скриптов

Игра автоматически загружает скрипты из файла `src/scripts/main.ts`.

Чтобы добавить свой скрипт:

1. Откройте файл `src/scripts/main.ts`.
2. Добавьте свой код с вызовом `ScriptRegistry.register(...)` внутри функции `registerUserScripts`.
3. Сохраните файл. Игра автоматически перезагрузится, и ваш скрипт станет доступен.

Пример `src/scripts/main.ts`:

```typescript
import { ScriptRegistry } from '../core/ScriptRegistry';

export function registerUserScripts() {
  ScriptRegistry.register('my.puzzle.win', ({ game }) => {
    game.showMessage('Puzzle Solved!');
  });
}
```

# Редактор cцены

Используется для создания/редактирования cцен и объектов. Включается по нажатию клавиши F1.
Визуально отображается как набор UI элементов за пределами пользовательского игрового экрана:

- левая панель (hierarhy): список объектов сцены и настройки сцены
- правая панель (properties): свойства выбранного объекта
- меню внизу экрана

## Меню редактора сцены

Визуально это oldschool кнопки с F-клавишами в стиле Norton Commander:
F1 Game F2 Save F3 Load F4 New F5 Sprite Edit F9 Settings

При нажатии Shift: F2 Save As...

Пользователь может нажимать на них мышкой или использовать клавиатурные сочетания.

- _Game_: Выключает редактор сцены и возвращает в режим игры
- _Save_: Сохраняет текущую сцену как JSON-файл
  Если это новая сцена, или нажато Shift-F2, пользователю открывается системный диалог сохранения файла, в противном случае сцена просто сохраняется под текущим именем.
- _Load_: Загружает сцену.
  Пользователю открывается системный диалог выбора файла.
- _New_: Создаёт новую сцену из файла шаблона (default).
  Если текущая сцена содержит несохранённые изменения, перед созданием или загрузкой новой сцены открывается системный поп-ап подтверждения.
- _Sprite_: Переход в редактор спрайтов.
- _Settings_: Открывает в правой панели глобальные настройки игры. Сейчас они ограничены только настройками шейдера CRT:
  - _CRT MODE on/off_: включает/выключает все эффекты CRT (серый фон, искажения, scanlines, abberations)
  - _CRT geometry_: задаёт степень "выпуклости" экрана
  - _CRT scanlines_: размер scanlines
  - _CRT abberations_: степень искажения цветов (chromatic aberration)

## Список объектов сцены (левая панель)

Здесь отображается список всех объектов сцены в виде буква типа объекта : имя объекта.
Возможные типы:

- _S_: Static
- _A_: Actor
- _W_: WalkBox
- _T_: TriggerBox
  Примеры: A:Player, S:Background01
  Длинный список может иметь ползунок прокрутки и может прокручиваться им, или колёсиком мыши при наведении на список.
  При нажатии мышкой на объект в списке он выделяется и открывается его настройки в правой панели.
  Также можно выделить объект, просто кликнув на него на игровом экране.

Для создания нового объекта достаточно нажать на клавиатуре горячую клавишу - соответствующую букву (<S> для Static и тд.), при этом новый созданный объект сразу выделяется.
Для удаления надо выделить объект и нажать на клавиатуре <Del>.
В качестве альтернативы можно создавать объекты мышью через UI кнопку Add в верхней части панели, которое открывает выпадаюший список с типами объектов (и подсказку про их горячие клавиши), а удалять выделенный объект через UI кнопку Delete.

Выделенный объект можно сохранить в файл для последующего использования с помошью UI кнопки Save (или нажатия <Ctrl-S>), что откроет системный диалог сохранения файла.
Объект также можно загрузить в текущую сцену из файла с помощью UI кнопки Load (или нажатия <Ctrl-O>), что откроет системный диалог загрузки файла.

Объекты в списке можно перетаскивать мышью, чтобы изменить их порядок. Также можно использовать клавиатурные шорткаты <Ctrl-Up> и <Ctrl-Down>.

## Настройки сцены (Scene Properties)

Это отдельный пункт в левой панели над списком объектов. Его нельзя удалить, можно только выделить. При выделении в правой панели открываются свойства сцены:

- _ID cцены_ (оно же имя файла при сохранении)
- _Переключатель Depth scaling_ (on/off)
- _Настройки Depth scaling_ (мин и макс. умножители масштаба, уровень горизонта и уровень переднего плана)
- _Настройки камеры_: текущие X/Y-координаты и Zoom, дефолтные координаты/Zoom, переключатель автоматического центрирования камеры на игрока, настройки автоцентрирования, настройки Depth scaling.
  Настройки камеры могут меняться как через редактор, так и динамически, прямо в игре, через игровую логику. Например, в кат-сцене камера может сделать zoom-out, переместиться с игрока на другой объект, а затем вернуться обратно и восстановить zoom.
  Если включено автоматическое центрирование, камера перемещается когда игрок подходим к краю экрана, что для пользователя выглядит как скроллинг.

## Отображение объектов на игровом экране в режиме редактирования сцены

Для удобства, все объекты типа WalkBox отображаются на главном игровом экране только тогда, когда выбран любой объект WalkBox в списке объектов, в противном случае они скрыты. То же самое с TriggerBox.

Пользователь может изменять текущий zoom сцены, нажимая на клавиши <+> и <->. Клавиша </> возвращает zoom к дефолтному значению.

Можно изменять координаты, на которые нацелена камера, заведя курсор мыши на игровой экран и двигая мышь с зажатой 2й кнопкой (<Right mouse button>), что будет выглядеть как скроллинг сцены на экране. При кажатии клавиши <\*> камера возвращается в дефолтное положение (центрируется на персонаже игрока, или на центр сцены).

Если пользователь сделал двойной клик на какой-то объект в списке на левой панели, то камера на игровом экране автоматически центрируется на этом объекте.

Выбранный объект выделяется на игровом экране пунктирной рамкой, даже если он находится за другими объектами и скрыт ими, рамка рисуется поверх. Взявшись за объект или его рамку мышью, можно перетаскивать объект и изменять его координаты.

При создании нового многоугольного объекта WalkBox или TriggerBox пользователь должен последовательно задать мышью все его точки, и затем нажать клавишу <Enter> для завершения создания объекта и превращения его в замкнутую область.
Если пользователь выбрал другой объект не завершив создание многоугольника, при повторном выборе этого незавершённого объекта создание многоугольника будет начато заново.
Если при этом зажать <Shift>, то текущая задаваемая точка будет двигаться так, чтобы образовывать лишь углы кратные 22.5 градусам, для облегчения проведения строго вертикальных/горизонтальных, а также параллельных диагональных линий.
Созданные многоугольные объекты WalkBox и TriggerBox можно редактировать, беря мышью за вершину многоугольника и двигая её. При этом также можно использовать <Shift> для ограничения движения вершины углами кратными 18 градусам.

## Настройки выбранного объекта (правая панель)

Здесь отображаются и доступны для редактирования все свойства выбранного объекта.

Для многоугольников тут также есть UI кнопка "Redraw", которая очищает многоугольник и запускает процесс его создания заново.

Для Static есть UI кнопка "Sprite", открывающая системный файловый диалог для выбора спрайта (JSON-файла, создаваемого в редакторе спрайтов).

У Actor, помимо текущего спрайта, как у Static, есть свойство "направление" (4 возможных варианта, которые можно переключать на панели, настраивая куда будет повёрнут этот Actor), а также устанавливать из скрипта.
Также есть визуальные состояния - группы (наборы) анимаций которые представляют собой добавляемые компоненты, отображаемые в панели свойств объекта. Каждый такой компонент имеет id, напр. "idle", и 4 спрайта для всех 4 направлений, которые можно загрузить по кнопкам '...' рядом с именем спрайта.
Каждая группа анимаций имеет кнопку "удалить" (пиктограмму с крестиком), которая вызывает поп-ап подтверждения удаления.
Также есть кнопка "Add Anim. Set" для добавления новой (пустой) группы анимаций.
Если у Actor вообще нет групп анимаций, первая добавленная автоматически получает id 'idle' а вторая 'walk' (но это пользователь потом может отредактировать)

Если текущмй спрайт не задан, то Actor будет выглядеть как Static без спрайта, то есть как прямоугольник с заливкой цветом.

Для Actor и Static можно задать размер их прямоугольника (ширина и высота) а также масштаб (умножитель размера). Например, можно уменьшать масштаб предмета, чтобы использовать для него спрайты более высокого разрешения без увеличения размера на экране.

### 6. Множественное выделение (Multi Selection)

- Поддерживается множественное выделение объектов сцены (Entity, Actor, Quad, Walkbox, Triggerbox).
- `Ctrl + Click` по невыделенному объекту добавляет его в группу выделения.
- `Ctrl + Click` по уже выделенному объекту убирает его из группы.
- В `Hierarchy Panel` работает тот же принцип `Ctrl + Click`.
- Перетаскивание левой кнопкой мыши по пустому месту канваса запускает прямоугольное выделение (рамка видна во время drag).
- Все объекты в группе подсвечиваются так же, как при обычном одиночном выделении.
- Любое обычное одиночное выделение (без `Ctrl`) завершает текущее групповое выделение.

#### Групповые свойства (правая панель)

- При выделении более одного объекта панель показывает заголовок `Selected N obj.`.
- Поля группы:
  - относительные `Group X / Group Y` (смещение от исходной группы),
  - относительный `Group Scale` (база = `1.0`, масштабирование группы с сохранением взаимного расположения),
  - `Layer`,
  - `Parallax` (если в группе есть Entity/Quad),
  - `Blend Mode` и `Blur` (если в группе есть Entity/Quad),
  - `Fill Color` (Entity/Quad),
  - `Line Color` (Quad),
  - `Group ID` (вводимые ID добавляются всем участникам группы).
- Для общих полей:
  - если значение одинаково у всех объектов группы, оно отображается;
  - если значения отличаются, поле отображается пустым (`mixed`);
  - установка значения применяет его ко всем объектам группы.
- Отредактированные значения группы сохраняются, пока существует текущее групповое выделение.
- Любое индивидеальное (обычное) выделение объекта, или снятие выделения, уничтожает группу выделения.

Параметры положения и масштаба (transform) в свойствах выделения являются относительными. Координаты X/Y соответствуют координатам неперемещённой группы. Пользователь может редактировать их напрямую в правой панели или перетаскивать группу мышью, при этом кординаты группы (выделенного множества) показывают куда она сместилась. Все объекты группы одинаково смещаются по этому вектору X/Y.
Аналогично работает Scale, только он не прибавляется, как координаты, а умножается на скейл всех объектов группы. Таким образом, неизменённый равен 1, а его изменения будет изменять масштаб всех объектов в выделении, например, установив scale группы в 0.5 пользователь уменьшит scale всех объекты вдвое. При изменении scale дожен происходиь пересчёт координат объектов группы чтобы они оставлались относительно друг-друна на тех же позициях. Например, два граничащих боками квадрата при уменьшении скейла не должны оторваться друг от друга, а при увеличении -- начать перекрывать друг-друга.
Остальные поля типа масштаба и слоя показывают реальные значения если они у всей группы одинаковы, или пустые (не заданные), если у группы они разные. их установка задаёт это значение всем объектам, входящим в выделение.

# Редактор спрайтов

Это отдельный от редактора сцены экран, со своим нижним меню и своей правой панелью, похожей на таковую в редакторе сцены, но с заголовком "Sprite Editor". Вместо игрового экрана в центре находится _рабочая область_ шахматного светло-серого/тёмно-серого фона (как в фотошопе), на которой отрисовывается текущее изображение (png с прозрачностью, шахматный фон просвечивает через прозрачные области).
Также на правой панели есть следующие редактируемые поля:

- id спрайта (оно же служит именем файа json)
- X/Y начальной точки области спрайта на изображении
- H/W размер кадра спрайта на изображении (начинается в начальной точке)
- кол-во кадров в анимации (1 если спрайт не анимированный). Каждый кадр расположен под предыдущим в линию по вертикали. Все кадры анимации имеют одинаковый размер.

Имеется область Preview, которая отображает текущий спрайт. Его размер автоматически подстраивается под размер области. Если спрайт анимированный, то он будет отображаться в цикле для всех кадров
Доп. настройки:

- скорость анимации в Preview
- переключатель остановки анимации и окошечо ручного выбора номера отображаемого кадра при остановленной анимации
- выбор фона Preview (чёрный, шахматный, ярко розовый)
- линии (rulers) показывающие центр спрайта по X и Y. Порядок отрисовки: фон -> rulers -> спрайт

Изображение может использоваться для нескольких спрайтов, то есть работает как атлас. Его можно загрузить из файла через UI кнопку "Load Image" на правой панели (хоткей Ctrl-O).
Над загруженным изображением отображается имя его файла.
Изображение при загрузке автоматически подстраивается под размеры области.  
На изображении в виде рамок отображаются все кадры спрайта, заданные в правой панели.

## Меню редактора спрайтов

F1 Scene Edit F2 Save F3 Load F4 New F5 Game

- _Scene Edit_: переход в редактор сцены;
- _Save_: сохраняет текущий спрайт как JSON-файл;
- _Load_: загружает спрайт из файла. При этом, в рабочую область загружается изображение, а в правую панель загружаются параметры спрайта;
- _New_: создаёт новый пустой спрайт;
- _Game_: переход в игру (закрывает редактор спрайтов);

# Техническая спецификация (Technical Specification)

## Настройка цветов редактора (Editor Theme Config)

Цвета пользовательского интерфейса редактора (Scene Editor, Sprite Editor) централизованы и могут быть изменены через CSS переменные.

### Основные переменные

Файл конфигурации: `src/index.css` (секция `:root`).

- `--ui-main-color`: Основной акцентный цвет (рамки, иконки, выделение текста). По умолчанию: `#79EFA4` (Bright Green).
- `--ui-bg-color`: Основной цвет фона панелей. По умолчанию: `#000000`.
- `--ui-panel-header-bg`: Фон заголовков панелей.
- `--ui-selection-bg`: Фон выбранного элемента в списках.
- `--ui-selection-text`: Цвет текста выбранного элемента.
- `--ui-label-color`: Цвет обычных текстовых меток.

### JavaScript / TypeScript доступ

Для использования цветов в коде (например, для отрисовки на Canvas) используется утилитарный класс `Theme`.
Файл: `src/utils/Theme.ts`.

Пример использования:

```typescript
import { Theme } from '../utils/Theme';

ctx.strokeStyle = Theme.mainColor; // Получает значение --ui-main-color
ctx.fillStyle = Theme.backgroundColor; // Получает значение --ui-bg-color
```

# Будущие технические возможности (Future Technical Features)

## Текстурированные Quads (Textured Quads)

\*Запланировано к рассмотрению при необходимости.\_

### Концепция

Использование QuadObject для создания текстурированных стен, полов и потолков с поддержкой перспективы.

### Техническая реализация (Canvas 2D)

Для оптимизации производительности в Canvas 2D (без WebGL) предлагается следующий подход:

1. **Геометрические ограничения**:
   - Дизайн уровней строится так, что камера **не вращается** (вертикальные линии остаются вертикальными).
   - Геометрия Quads ограничивается:
     - **Прямоугольники / Параллелограммы** (стены в анфас, плоские полы).
     - **Трапеции** (стены и полы, уходящие в перспективу).

2. **Рендеринг**:
   - **Affine Mapping**: Использование аффинного наложения текстур. Для трапеций это требует разбиения Quad на два треугольника с UV-координатами.
   - **Tiling (Тайлинг)**: Поддержка повторения текстуры (Tile X, Tile Y) для заполнения больших площадей маленькими текстурами (экономия памяти).

3. **Данные**:
   - В `QuadObject` добавляются свойства: `textureName` (string), `tileX` (number), `tileY` (number).
   - В редактор добавляется выбор текстуры и настройка тайлинга.
